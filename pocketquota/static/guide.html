01 / 建立账本

服务启动后，从数据目录的 admin.token 取得管理员登录口令。首次进入填写当前资金池余额、每日限额和时区。时区在初始化后固定，避免更改后同一天被重复结算。默认使用人民币，金额精确到分。

演示模式使用虚构数据，可自由试用；演示数据与正式账本请使用不同数据目录。一个实例服务一个个人账本，多个 Agent 可以协作访问；不是多租户网站。

02 / 三个资金池，一套额度

资金池 作用 如何选择
日常池 承担日常消费，并受每日限额约束 默认选择
灵活池 接收每日结余，承担日常不足和额外消费 可直接指定，不计入每日限额
保底池 独立保留的预算 仅明确选择时使用，永不自动补足
示例

每日限额 ¥60，今天已经花了 ¥50，再从日常池记一笔 ¥25：日常承担 ¥10，灵活承担 ¥15。如果日常池实际只剩 ¥3，则由日常承担 ¥3、灵活承担 ¥22。流水中会显示实际拆分。

每日限额是消费约束，不是一笔新收入。每天零点仅重置额度计数，绝不凭空给日常池增加资金。支出已发生时，即使超额也会如实记录；资金池允许出现负数，用于暴露缺口。

可消费预算 = 日常池 + 灵活池。合计 ≤ 0 时，整页进入红色“赤字 · 已破产”状态；这是个人预算提示，不是法律意义的破产认定。保底池不计入可消费预算。

“记一笔”支持支出、收入和池间转账，可指定日期与资金池。“预算与规则”可修改池余额，必须填写原因；系统新增差额记录，不覆盖旧账。

03 / 每日结算与补记

在设定的时间把未用额度从日常池转入灵活池，最多转移日常池实际可用余额，不生成虚拟资金。超额支出在记账时已由灵活池承担，结算时不会再次扣款。

  • 可以提前结算；同一日期反复结算不会重复划走资金。
  • 结算后补记或撤销，会重新计算当日承担额及结余差额，相关冲正保留在流水里。
  • 日限规则从今天或未来生效，历史规则保留。降低当日限额可能重新分配已结算的日常／灵活承担额。
  • 跨日补记会改变历史余额；此前的对账记录会标为“需复核”。
  • 对账是核对余额，结算是划转额度，两者相互独立。

04 / 每日、每月对账

选择日期或已结束的月份，先看账面余额，再填写三个池的实际核对金额。系统记录差异，不自动“调平”。有差异时先检查遗漏、重复、退款和池归属，再决定是否调整余额。

每月按设定日期和时间生成上月待对账项目。没有人工核对，不会标成已对账；后续补记造成变化时需要再次复核。

流水可导出 CSV。原记录不能直接抹除；发现记错时先撤销，再重新记账。撤销行为、原流水和执行来源都会保留。

05 / 每日补贴与每月自动入账

在“预算与规则 → 自动入账计划”设置金额、资金池、日期、时间与频率。支持每日及每月。设为每月 31 日时，二月等短月使用当月最后一天。计划可以修改或暂停。

后台每 30 秒检查一次。服务离线期间不执行；恢复后按时间顺序补记到期项目。同一计划同一期仅入账一次。新建或修改的计划从当天起生效，不追溯补发更早月份。

自动入账只是记账，不会发起银行扣款或转账。请仅为确定到账的资金设置自动计划，否则实核对账时会出现差额。

06 / 连接 Agent

先在“Agent”页创建独立令牌。只读令牌只能查账；读写令牌可记账、撤销、对账和确认通知。需要通过 Agent 对话管理预算时，可显式选择“预算管理”权限；该权限可修改规则、计划与池余额，但仍不能创建其他令牌或提升权限。默认只读。

支持标准 MCP stdio，也提供 REST API 与 OpenAPI 文档。Codex、Claude Code / Desktop、Cursor、VS Code Copilot、Gemini CLI 的示例在仓库 integrations/。不支持 MCP 的框架可以调用 pocketquota.mcp.call() 或 REST。 

{
  "mcpServers": {
    "pocketquota": {
      "command": "python3",
      "args": ["-m", "pocketquota.mcp"],
      "env": {
        "POCKETQUOTA_URL": "https://budget.example.com",
        "POCKETQUOTA_TOKEN": "<专用令牌>"
      }
    }
  }
}

在 Agent 所在机器安装本项目，Python 使用该环境的可执行文件。远程地址必须使用有效 HTTPS 证书；MCP 桥接不跟随重定向，不发送密钥到其他地址。这里的 https://budget.example.com 是占位示例。

避免重复记账

每个独立记账请求生成稳定的 request_id（REST 使用 Idempotency-Key）。网络重试必须复用同一个键；相同键搭配不同内容会被拒绝。记录金额使用字符串，如 "12.50"；返回金额以整数分为单位。

赤字通知

预算第一次耗尽时生成一条通知事件。持续赤字不再新增；恢复后再次耗尽则生成新事件。指定一个通知 Agent 定时读取 budget_notifications，仅在获得用户授权的私聊中发送，成功后调用 budget_ack_notification。空列表保持安静。

需要在你的 Agent 宿主中配置这个通知任务，MCP 工具本身不会自主运行。WebUI 不直接联系 QQ、邮箱等渠道。投递使用至少一次语义：通知程序应按事件 ID 去重，不能在投递失败时提前确认。

07 / 外观与动效

右上角“外观”可选深空黑或极简白、线形光轨或圆环、三套光谱，以及主条显示今日额度或总预算。

支出成功后额度出现粒子消散，收入成功后出现光带汇入。动画不改变金额。收入不会自动增加每日限额；想直观看到入账变化可把主条切到“总可消费预算”。系统开启“减少动态效果”时会自动停用动画，也可以手动关闭。外观偏好保存在当前浏览器。

08 / 数据与部署边界

  • 无外部字体、图片、分析统计或第三方前端脚本。
  • 数据库在你的部署实例中；没有云同步或银行连接。
  • 网页使用 HttpOnly 会话 Cookie；Agent 令牌在数据库中只存哈希。
  • 令牌和实际账目不得上传到公开仓库。备份时使用 SQLite backup API，不能只复制运行中的主数据库而忽略 WAL。
  • 首次公开版本为个人自托管版。公网使用请放在 TLS 反向代理后并设置精确的 POCKETQUOTA_ORIGIN。
